このタブを直すとき用のメモ。中村様は普段開かなくてOK。ClaudeやエンジニアがあとでこのHTMLを見れば、しくみをすぐ思い出せるように書いてある（別ファイル『輸入準備計算_説明書.md』と同じ内容）。プレフィックスは prep* で自己完結。既存関数は変更していない。
このアプリEには、しくみの別グループがもう1つある：「🌿 農園とのやり取り記録と改善」タブ＝プレフィックス tr*（下の専用セクション参照）。prep* とは別物で、混ぜない。

置き場所

  • ファイル：import.html（アプリE／輸入・原価）。タブは既存の showPanel('name',this) 方式。タブ行に showPanel('prep',this) ボタン、showPanel() 内に if(name==='prep') prepRender(); を1行追加。
  • パネル本体は <div id="panel-prep" class="panel">…</div>。JSは末尾の <script> 内に prep* で追加。

データモデル

  • PREP_PRODUCTS：商品配列。各フィールド＝ id(不変キー), sku(自社品番・編集可), name(日本語名), cat, vol, cont(容器 瓶/缶/箱), rt(RT社内コード＝セット照合キー), box(入数＝1箱の本数), res(直接予約), stock(現在庫), target(★残したい販売在庫), exp(賞味期限), lblLang, lblPrint, lblColor, lblUrl(裏ラベル画像URL), enName(英語名の上書き)。
  • PREP_SETS：セット構成。{set:RTコード, comp:中身のRTコード, qty:1セットあたり本数} の配列。照合はRTコード。
  • グローバル：prepMode({id:'up'|'down'}), prepHistory(確定記録配列), prepFolderUrl(農園共有フォルダURL)。

⚠️ RTコード（rt。例 4101229）はRT社内の番号。自社の商品管理番号（品番＋バーコード下4桁。例 ORG500-5354）とは別物。混同するとミスになる。自社側の唯一の正は名簿（master.html / TurboMaster）。

計算ロジック prepCalc()

  • setDerived ＝ Σ（PREP_SETS のうち comp==p.rt の行）qty × そのセット商品のres
  • remain（出荷後に残る数）＝ stock − res − setDerived（マイナス可＝不足）
  • want（輸入したい本数）＝ max(target − remain, 0)
  • box有：切上 up=ceil(want/box)・upN=up×box・upSur=upN−want／切捨 down=floor(want/box)・downN=down×box・downSh=want−downN。finalBox＝prepMode[id]が'down'ならdown、既定up。finalN=finalBox×box。【2026-07-31 変更】画面の「▲切上／▼切捨」の選択ボタンは廃止し、丸め列は「✏ 手で決める」だけにした（中村様指示：丸めはClaudeが自動で計算するので手選択は不要）。up/down/upSur/downSh は今も内部で計算しているが画面には出さない。既定は常に up（＝箱がぴったり埋まる切上）で最終箱数を表示。prepChoose(id,mode) 関数は残置（未使用・無害）。手で変えたいときだけ prepManualOn(id) で手入力に切替（finalBox/finalN を初期値に、以後は p.manual/manualBoxes/manualN が優先）。
  • box無：finalN=want, finalBox=null
  • realRemain（実際に残る販売在庫）＝ remain + finalN

描画

  • prepRender()：メイン表。先頭で一度だけ localStorage→(あれば)GAS読込。末尾で prepRenderOrderEN() / prepRenderHistory() / prepRenderFolder() / prepSaveLocal()。
  • prepRenderOrderEN()：英語表。prepEnName()(enName優先), prepEnCont()(瓶→Bottle等)。賞味期限・言語・印刷地・色・URLは商品ごとのinput/select。#prep-folder-en に農園共有フォルダをコピー表示。
  • prepRenderHistory()：prepHistory を年ごと見出し＋日付ごと details で新しい順表示。
  • prepRenderFolder()：#prep-folder-url と #prep-folder-link を prepFolderUrl に同期。
  • 同梱依頼物（copack）＝オイル以外で「箱に一緒に入れてほしいもの」。データ＝prepCopack 配列 {name, qty, unit, tr(品目名のトルコ語), memo, trUnit(単位のトルコ語), trMemo(メモのトルコ語)}。編集表＝prepRenderCopack()／農園向け表＝prepRenderCopackEN()（見出し「📦 Koliye eklenecekler」）。【2026-07-31 変更】農園に送る書類なので"品目名だけ"でなく単位・メモも含め全項目をトルコ語にした。農園向けはトルコ語(大)＋日本語(小)の二段：copackBiCell(tr, ja)。トルコ語が空なら日本語を大きく出し「（トルコ語 未記入）」を添える。ハンドラ prepCopackAdd/Del/Set。翻訳ボタン prepTranslateJaToTr()＝同梱依頼物（品目名・単位・メモ）＋備考の日本語をまとめてトルコ語化して各trフィールドに入れる（日本語は残す）。翻訳はGASの translateBatch（LanguageApp）。
  • 選択肢定数：PREP_LANG_OPTS / PREP_PRINT_OPTS / PREP_COLOR_OPTS / PREP_CONT_OPTS。
  • 編集ハンドラ：prepSetFree(在庫・目標=確認なし), prepSetRes(予約=確認あり), prepEditMaster(品番・容量・容器・入数=クリック＋確認), prepSetLbl(英語表の各項目), prepBulk(一括), prepSetFolder, prepChoose(箱丸め)。

確定・記録

  • prepFinalize()：finalN>0 の行をスナップショットして prepHistory.unshift()。形＝{id, date(ISO), dateStr, memo, folderUrl, total, items:[{jpname,enName,sku,vol,cont,box,finalBox,finalN,exp,lang,print,color,url}]}
  • prepDeleteHistory(id)：確認のうえ1件削除。

保存（永続化）

  • 状態の形：{v:1, mode, history, folderUrl, p:{ id:{s,r,t,b,name,sku,vol,cont,exp,lblLang,lblPrint,lblColor,lblUrl,enName} }}
  • prepBuildState() で作り prepApplyState() で戻す。
  • localStorage：キー oos_prep_state_v1（prepSaveLocal/prepLoadLocal）。
  • GAS：prepGasSave()=POST savePrepState / prepGasLoad()=POST getPrepState。既存 GAS_URL と password(=COST_DATA_PASSWORD) を流用。1.5秒デバウンス、初回オープンで一度 prepGasLoad。
  • 堅牢化：GASのPOST応答は googleusercontent へリダイレクトされ fetch で応答本文を読めないことがある（書込は成功しているのに）。prepGasSave は応答が読めないとき getPrepState で読み直し state===payload 一致なら成功と判定。失敗表示は琥珀色に緩和。

GAS側（サーバー）

  • 追加関数は2つ：savePrepState(password, stateJson) と getPrepState(password)。パスワードは COST_DATA_PASSWORD。
  • 保存先：スプレッドシート「輸入準備計算保存」シート。A1=state(JSON文字列)、B1=保存日時。空/{}は保存拒否（消さない安全装置）。
  • doPost に2行、doGet に任意で getPrepState 1ブロック。反映は必ず『デプロイを管理→既存デプロイを編集→新バージョン』（新規にするとURLが変わる）。完成版一式は GAS_完成版_これを全部貼り付け.gs。

よくある変更のやり方

  • 商品を足す/減らす：PREP_PRODUCTS に要素を追加/削除（id,sku,name,cat,vol,cont,rt,box,res,stock,target を埋める）。英語名は自動、必要なら enName で上書き。
  • 入数を変える：box を変更（名簿 master.html の boxQty と一致させる）。
  • セット構成を変える：PREP_SETS を編集（RTコードで set↔comp）。
  • 目標の初期値：PREP_PRODUCTS[].target。箱丸め既定：prepCalc の mode=prepMode[p.id]||'up'（常に切上）。丸め列は「✏ 手で決める」だけ（切上/切捨ボタンは2026-07-31に撤去）。もし切上/切捨の手選択ボタンを復活させたいときは prepRender の choose 生成（r.box>0 の分岐）に prepChoose(id,'up'/'down') ボタン2つを戻す。
  • 言語/印刷地/色/容器の選択肢：PREP_LANG_OPTS / PREP_PRINT_OPTS / PREP_COLOR_OPTS / PREP_CONT_OPTS。英語名マップ：PREP_EN_NAME と prepEnName の分岐。

注意点

  • RTコード ≠ 自社商品管理番号。突合は名簿(TurboMaster)を唯一の正として。
  • GitHub Pagesのキャッシュ：差し替え後はスーパーリロード。
  • prep* 以外の既存関数・データは触らない。
  • 状態JSONは『輸入準備計算保存』A1の1セルに全部入る（約5万文字まで）。将来とても大きくなるなら履歴だけ別シート化の余地。

🌿 農園とのやり取り記録と改善タブ（プレフィックス tr*・2026-07-31 新設）

  • 目的：農園（Novavera）との過去トラブル台帳（全21件・以前ムスタファさんとのWhatsAppから拾い出し）を残し、右端「✍️ その後の対応」にいつ・どう対応したかを書き込み、決めごとにしたいものを上の「📌 ルール化するもの」枠にためていく。
  • 置き場所：パネル <div id="panel-trouble" class="panel">。タブ行に showPanel('trouble',this) ボタン、showPanel() 内に if(name==='trouble') trRender(); 。JSは prep* とは別に tr* で自己完結。
  • ルール枠：5カテゴリ（書類／ラベル／賞味期限／梱包／その他）＋自作カテゴリ。1件＝1行の箇条書き（枠なし・色バー＋見出し＋箇条書き、空カテゴリは「（まだ無し）」を1行）。クリックで編集(trRuleInput)／🔴赤(trToggleRed)／🗑削除(trDelRule)／右の選択で分類変更(trRuleCat)／Enterで同カテゴリに次行(trAddRuleAfter)。台帳の各行「→ ルールに移す」(trMoveToRule)は、その行の「分類」からカテゴリを推定(trCatFromBunrui＝キーワード一致・不明はその他)して、対応内容を該当カテゴリに入れる。
  • 描画：trRender() → trRenderCatBtns() / trRenderRules() / trRenderTable()。台帳は横スクロール表(min-width 1180px)。
  • 保存：既存の saveStickyMemo / loadStickyMemos を専用シート「農園トラブル対応」（定数 TR_SHEET）で流用＝GAS改修なし。localStorage は trSaveLocal/trLoadLocal、GASは trGasSave/trGasLoad（既存 GAS_URL＋password＝COST_DATA_PASSWORD）。頼みごとメモ等の他データには触らない安全マージ。
  • 注意：tr* と prep* を混ぜない。台帳の初期21件はコード内の配列（TROUBLE系）に持つ。「その後の対応」とルールだけが保存対象。
